🤖 AI Project Builder

اكتب فكرة برنامجك باللغة الطبيعية. هنساعدك تحولها إلى طلب تطوير واضح، من غير كتابة كود.

مهم: الإصدار الحالي مساعد لتجهيز مواصفات المشروع، وليس وكيل AI ينفّذ الكود تلقائيًا. إنشاء GitHub Issue يحتاج تسجيل الدخول ومراجعتك للطلب. لا نرسل وصفك لأي خدمة AI خارجية.

2. راجع خطة المشروع

المواصفات التالية مُنشأة من مدخلاتك وقائمة فحص ثابتة. راجعها وعدّل الوصف قبل إرسال الطلب.

بعد نشر الطلب على GitHub، سيرسل نظام استقبال الطلبات مواصفات المشروع إلى Pull Request للمراجعة تلقائيًا. تنفيذ كود المشروع نفسه ما زال يتطلب مطورًا أو وكيلًا برمجيًا مُفعّلًا. يتطلب حساب GitHub.


🧭 مراحل تنفيذ المشروع
دي خريطة المراحل المتوقعة، وليست حالة مباشرة لطلب معين.
  1. Request submitted — إنشاء GitHub Issue بعد موافقتك.
  2. Specification PR — تجهيز مواصفات للمراجعة تلقائيًا.
  3. Agent coding — غير متاح حاليًا؛ يتطلب محرك AI مصرحًا به.
  4. Tests and review — متاح للمشاريع التي تم تنفيذ كودها.
  5. Release — بعد مراجعة ودمج مشروع فعلي.
إنشاء Issue أو PR مواصفات لا يعني أن التطبيق اتبنى. لم يتم تفعيل أي API مدفوع.
📍 متابعة الطلبات من هنا
بعد إرسال الطلب، تابع حالته ونتيجة تشغيل الأتمتة مباشرة. لا تحتاج ترجع للشات.
طلبات المشاريع ↗مواصفات قيد المراجعة ↗حالة الأتمتة ↗
دي روابط متابعة مباشرة على GitHub وليست حالة حية داخل الصفحة. ربط حالات التنفيذ المباشرة محتاج تكامل إضافي.
3. ماذا يحدث بعد إرسال الطلب؟
  • يتم تسجيل فكرتك كـ GitHub Issue بعد موافقتك، ويولّد GitHub Actions ملف مواصفات وPull Request للمراجعة تلقائيًا.
  • تُراجع المتطلبات، وتُحدد الملفات والاختبارات المناسبة.
  • ينفّذ مطوّر أو وكيل برمجي مُفعّل صراحةً المشروع في فرع منفصل.
  • بعد نجاح الاختبارات ومراجعة Pull Request، يُدمج المشروع وتظهر أداة التشغيل في Dashboard.
المراحل البرمجية الأخيرة ليست مؤتمتة بالكامل حاليًا.
